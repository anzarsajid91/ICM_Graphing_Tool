# Contributing to HydraBench

Use issues for reproducible defects or proposed changes and pull requests
for patches. Submit original changes under [GNU AGPLv3](LICENSE) under the
same terms as the project. Keep rights notices and identify the source,
authors and licence of any proposed third-party code or assets.

Read [AGENTS.md](AGENTS.md) and [SECURITY.md](SECURITY.md) before working
with the code. Use synthetic fixtures in shared issues, tests and screenshots.
Keep imported data, identifying metadata and results inside the browser.
Follow the private reporting instructions in the security policy for
suspected vulnerabilities.

Explain changes to numerical methods, units, time support or validity and
include reproducible reference checks. Run the relevant repository checks
and report what passed. Upstream changes use the existing code ownership,
security review and release controls.

Release candidates require both expert verdicts under the
[Dual-Expert Review Framework](docs/dual-expert-review.md). Give reviewers
the candidate revision, a synthetic reproduction, expected engineering
outcomes and the evidence needed to check them. Record findings, decisions and
reassessment in the [release review history](docs/reviews/README.md).
