# Hydra Bench v3.0.1 · Independent product design and engineering UX review

Agent B · First pass · 24 November 2026

## Scope and decision

I reviewed the public GitHub Pages release in fresh desktop Chromium 140 and Firefox 141 contexts. The footer and page metadata reported v3.0.1 and `ccc36427c12f003e5d9b1fee61632770b31952cc`, which matched the exact-source worktree. I used the supplied synthetic expanded network, generated synthetic series, and the repository's synthetic assessment files. Browser runs used the repository request observer and added a route rule blocking application requests that violated the same resource contract. The exercised requests passed the observer. The simulation component retry used a deliberate one-time abort of its fixed script request. This tells us how the tested screens responded. [Live release](https://anzarsajid91.github.io/ICM_Graphing_Tool/) · [Chromium inventory](logs/inventory-chromium.json) · [Firefox inventory](logs/inventory-firefox.json)

The engineering schematic makes the pump, control and outlet routes much easier to follow than the geographic view at overview scale. The largest remaining UX costs are the loss of orientation and context when drilling into a constrained canvas, hard-to-read layout controls in reporting, and the absence of keyboard equivalents for exact point inspection and playback readouts. Prioritise the two verified access barriers and the network context handoff before broad visual changes.

**Priorities.** P1 is a common task with an inaccessible control or meaningful risk of overlooking evidence. P2 is repeated decision-making friction or a missing aid with a usable workaround. P3 is a lower-impact improvement. Severity refers to the observed experience and a specific task.

## Findings

### B-01 · Report options clip at standard desktop width · High / P1 · Verified

At 1024 px, Reports › Report generation › Report options positions its Collapse control at x965–1054. Its clipping parent ends at x974, leaving 9 px of the 89 px button and no readable label. The nominal page scroll width still equals 1024 px. Firefox inventory also records the right edge at x1054. At the same width Data › Rainfall events places the minimum event duration input partly beyond the viewport (right edge x1039); the centre remains operable in Chromium. This exposes a common weakness in internal regions with fixed/min-content columns. [Report options](screens/a11y-report-1024-chromium.jpg) · [Rain settings](screens/a11y-rain-1024-chromium.jpg) · [Geometry](logs/results-a11y-chromium.json)

**Acceptance.** At 1440, 1366, 1024 and the effective width of a 1366 desktop at 200% zoom, each Report options action and Rainfall events field must fit the visible region or have an obvious keyboard-operable overflow container. At 1024 px the full Collapse target and focus ring must be visible and pointer-clickable at its centre. No section label may wrap inside a word. Keep model scenario selection and section ordering intact.

**Implementation and regression risk.** Fix nested grid min sizes, header wrapping and single-column fallback before adjusting global shell overflow. Test the actual ancestor clipping rectangle and hit testing as well as document scroll width. Cover long scenario names, sidebar collapse, inspector open/closed, and report reordering and export scope.

### B-02 · Exact time-series point inspection needs a keyboard path · High / P1 · Verified UI and source

The rendered Point inspector instructs users to click a trace. Plot controls are exposed as focusable nodes, but the chart offers no adjacent keyboard control to choose a trace and move among its timestamps. The inspected implementation wires the point inspector to Plotly pointer events. The user can inspect a chart visually yet has no equivalent path to populate the exact timestamp/value readout and Copy point with keys alone. [Loaded time series](screens/journey-data-chart-chromium.jpg) · [Chart DOM](logs/journeys-chromium.json)

**Acceptance.** Using only Tab and arrow keys or a trace/time picker, locate three exact source samples on a synthetic trace, including a missing value and duplicate-looking time labels in different source series. The focused control and readout identify the series, project-clock timestamp, value and unit. Copy point uses that same value. Visible focus, date interpretation, unit conversions and downsampling behavior remain consistent with pointer selection.

**Implementation and regression risk.** Provide a compact accessible sample navigator or table backed by the existing point-inspector formatter. Keep bounded page cost on long records. Cover inclusions/exclusions, visible-window versus native samples, download and chart keyboard shortcuts. [Exact source](https://github.com/anzarsajid91/ICM_Graphing_Tool/blob/ccc36427c12f003e5d9b1fee61632770b31952cc/web/assets/workbench-v2.js#L295)

### B-03 · Preserve network orientation when narrowing or opening evidence · Medium / P2 · Verified

A common path is to Fit, recognise a control, then open its evidence. With the inspector at 1024×768, Fit leaves only six of the 14 Engineering labels and hides PS-01 and OUT-MAIN text. Full screen helps, though five node labels remain suppressed. The same panel also carries evidence, review notes and edit actions, so engineers must keep opening it. Detailed view adds 202 focusable SVG targets to the DOM on this fixture, and reaching the desired target by sequential tab is inefficient. Search successfully selected W-06 and retained it across views, providing a working short path. After clearing a downstream trace, the full 14-point Engineering diagram returned but the status still read `Showing only the traced branch.` [Canvas comparison](screens/network-audit.jpg) · [Exact dimensions](logs/network-chromium.json)

**Acceptance.** On the 101-node fixture at 1024×768, opening evidence for W-06 preserves a clearly highlighted position or offers a keyboard-visible Fit selection action, keeps readable named anchors for the split, pump, CSO, merge and both outlets, and allows returning to the overall extent with one action. Keyboard users can get from Find asset to the selected inspector, action tools and back without traversing every visible connector. Grouped, manually pinned and traced views retain their own selection and extent behavior. Clear trace and search must synchronise the status, pressed state and visible scope.

**Implementation and regression risk.** Establish adaptive inspector placement and named-anchor label priority before tuning minimum font size. Offer direct focus transitions or navigable asset lists while retaining keyboard reachability for individual nodes and connectors. Exercise route tracing, real keyboard canvas editing, separate camera states and existing hide/fit behavior across the three modes.

### B-04 · Make collapsed reaches and view intent visible in the network and exports · Medium / P2 · Verified

The 101-link source becomes 14 drawn connectors in both simplified modes, but the difference is communicated primarily in tool interactions. A straight reach representing 13 source links looks much like a one-link connection at rest. The Strategic feeders are both named Upstream branch, with counts 9 and 6. On all three exports the suggested SVG filename is `hydra-network-schematic.svg`, and the SVG root is named `Network diagram`. I supplied a custom title for screenshot comparison. The product's legend distinguishes geographic from schematic positions but omits the active schematic mode, simplified scope and represented/source counts. This leaves a reviewer reconstructing what the view means when its file travels outside the workbench. [View comparison](screens/network-audit.jpg) · [Exports](outputs/network-engineering-chromium.svg) · [Strategic SVG](outputs/network-strategic-chromium.svg)

**Acceptance.** Automatically display the view mode and simplification scope in each diagram and default publication. State visible points/connectors alongside represented source counts or clarify the active subset, and give grouped feeders distinguishable origin/destination cues. On the supplied fixture a reader can identify the 13-link reach and the two feeder groups without relying on hover. Suggest a mode-specific filename. Provide a meaningful SVG accessible name and a short description or equivalent companion summary. Retain explicit nominal direction and on-screen/output consistency for filtered, traced and visible-area exports.

**Implementation and regression risk.** Reuse current graph constituents and prefer one derived metadata model for the live legend, SVG, PNG and PDF. Keep annotations optional where necessary for publication legibility. Do not infer physical geometry or actual flow from nominal topology. Preserve route provenance and local-only export.

### B-05 · Expose the current simulation sample to keyboard and assistive technology · Medium / P2 · Verified

The native slider responded to Home and ArrowRight on a three-record synthetic CSV. The visible sample correctly distinguished 0 m³/s, a missing record and −0.4 m³/s on irregular project-clock times. The accessible slider exposes the numeric index 0–2 and no `aria-valuetext`. Its sample paragraph has no live semantics. A screen-reader user has no immediate value/time equivalent while carrying out the otherwise working keyboard workflow. Actual speech behavior was not tested. [Loaded review](screens/journey-results-review-chromium.jpg) · [DOM and sample evidence](logs/results-a11y-chromium.json)

**Acceptance.** At indexes 0–2, the accessible value includes timestamp, unit and numeric or Missing state. Previous/Next and direct keyboard changes produce the same result. Playback provides a deliberate readout on pause/step without continuously announcing every change. No regression in sample-window bounds, offset and negative/zero handling.

**Implementation and regression risk.** Update the transport's accessible value from its existing selected-series formatter. Keep high-frequency playback output separate from deliberate user announcements. Add Chromium and Firefox accessibility assertions for exact states. [Exact source](https://github.com/anzarsajid91/ICM_Graphing_Tool/blob/ccc36427c12f003e5d9b1fee61632770b31952cc/web/assets/simulation-results.js#L177)

### B-06 · Put the next required action beside blocked work · Medium / P2 · Verified

On a fresh tab, Generate scatter reports `Operation failed: Apply an observed and at least one modelled series first.` Focus stays on Generate scatter, and the workflow exposes no contextual link to Data and assignment. Network › Schematic initially presents an empty canvas. Its only primary import affordance is under `Save / Export / Load`, beside publication controls for work the user has yet to load. Detriment's `Open data sources` empty-state action shows the better pattern. [Verification empty](screens/journey-verification-empty-chromium.jpg) · [Empty network](screens/viewport-network-1024-firefox.jpg) · [Detriment example](screens/34-detriment-default-chromium.jpg)

**Acceptance.** From a new session, someone entering Verification or Schematic directly can reach the required data or import chooser in one clearly labelled action. A failed calculation identifies unmet requirements and gives a keyboard-accessible route or focus jump. A first failed network import leaves a visible way to select another file, and experts retain fast access to the existing actions.

**Implementation and regression risk.** Reuse current file inputs and route links. Expose actions from the actual readiness model. Test unassigned, assigned-but-incompatible, stale and valid evidence without suppressing legitimate error detail or auto-accepting project assumptions.

### B-07 · Make Partial readiness actionable at report time · Medium / P2 · Verified

With a current synthetic comparison and spill result, the report cards show `Partial` with the explanation `Dependencies match the current analytical state.` That tells the engineer freshness but the card does not identify the cause of Partial or the action that resolves it. At 1024 px, several readiness card titles are ellipsised. The actual report retained the synthetic verification decision and source provenance. [Readiness and artifact metadata](logs/journeys-chromium.json) · [Report header at 1024 px](screens/a11y-report-1024-chromium.jpg)

**Acceptance.** For a Partial comparison/spill or absent survey association, show which component is partial or absent, the relevant evidence basis, and the shortest return path to inspect or resolve it. A deliberately partial report still exports faithfully with the same evidence status. Card title and status are readable at 1024 px.

**Implementation and regression risk.** Attach reason metadata to the existing result readiness rather than inferring it from presentation text. Regression cases need valid, stale, partially covered and deliberately omitted results. Preserve export provenance and exact section selection.

### B-08 · Provide a skip action and clear long-workflow start points · Medium / P2 · Verified skip gap, discoverability hypothesis

Fresh Tab presses traversed the rail toggle and nine workspace choices, with visible outlines. The DOM inventory found no skip-to-main action. Back navigation and tab-arrow selection worked, so the gap concerns repeated access to the main workspace. In Flow survey the repeated header gives valuable status, but `FDV check`, `Assessment settings & methodology` and the separate `Survey configuration · fm_rg_assoc.xlsx` disclosure defer the obvious sequence for someone without a supplied setup. The guide on Home helps users who enter through it. [Keyboard sequence](logs/inventory-chromium.json) · [Survey entry](screens/12-survey-default-chromium.jpg)

**Acceptance.** The first keyboard action reaches the active page heading or its main landmark in one extra Enter. Preserve route tabs and focus return from dialogs. In a fresh survey session, show the required local source categories and a direct path to the association chooser beside the relevant readiness row. Validate a new user can identify the missing prerequisite from FDV and Monthly review without opening exploratory panels.

**Implementation and regression risk.** Implement the skip target in the shared shell and use existing routes and upload controls. Preserve reading order, sticky header offsets, Back/Forward and saved workspace behavior. Validate the survey discoverability hypothesis with a short task-based walkthrough.

### B-09 · Describe the scope of evidence export actions in Detriment · Low / P3 · Verified labels, comprehension untested

The compact header offers `Export full CSV`, `Export full assessment`, `Export current view CSV` and `Export current view` together, before filters and selection controls. At 1024 px they push the primary action onto a second row. The wording distinguishes full/current but makes output format and the meaning of full harder to scan. `Full` can also mean all evaluated rows within an applied ID scope. [Detriment at 1024 px](screens/viewport-detriment-1024-firefox.jpg)

**Acceptance.** Each export action tells the reviewer its actual local format and the count/scope of rows, including a filtered grid and a manually applied asset list. The engineer can still run Calculate detriment and choose each existing export with keyboard and pointer at 1024 px. Verify a filtered export contains exactly the displayed scope and the full export retains all assessments within the applied ID scope.

**Implementation and regression risk.** Clarify current actions or combine them under one labelled disclosure while leaving export source datasets and file formats intact. Regression-test full versus current view, applied IDs and unresolved assets, source fingerprints, and local-only operation.

## Evidence limits and reproduction

The review used synthetic inputs, desktop widths and the repository's supported browser engines. The expanded network tests topology and visual context. It does not contain full profile or overtopping geometry. Readability findings apply to the observed fixture and widths. Effective narrower desktop widths stand in for reflow inspection. Actual browser toolbar zoom, screen reader speech, external or assistive software, other OS/browser versions, large live projects and broad contrast compliance remain untested. Secondary calculators, storage methods, all scenario result overlays and all report permutations received bounded inspection. Evidence was left in local files. No application code, deployed artifact, or repository state was changed.
