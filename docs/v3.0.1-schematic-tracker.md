## Layout decision

- A pinned evaluation compared ELK.js 0.11.0, Dagre 2.0.1 and the first domain-specific implementation against the same reduced graphs. For the nine-point survey reference, the old layout had four proper center-line intersections and six diagonal segments. The new router, Dagre and ELK each had zero proper intersections in that run. Only the new router and ELK produced all-orthogonal paths. Median Node times across seven repetitions were 1.10 ms, 3.01 ms and 17.88 ms respectively. The branched reference showed the same distinction. Those measurements count geometric intersections and do not measure overlaps or labels, which are checked in browser captures.
- The selected implementation uses a tributary-band layout for single-outlet trees and a layered arrangement with dedicated connector ports for other components. It uses no runtime dependency. ELK's reviewed package has a large bundled footprint and uses EPL-2.0. Dagre's MIT-licensed arrangement required a separate orthogonal routing engine for this use.
- The deterministic mixed fixture verifies two CSOs and outfalls, parallel links, cycles, pump and rising main, explicit overflow and return routes, weir, orifice, reversible sluice and isolated component. Every source connector is accounted for once. The retained points preserve nominal reachability. The 10,001-asset branched fixture took 347 ms for Engineering and 61 ms for Strategic in the local Node run. Strategic exposes 469 points and 468 connectors before branch expansion.
- The first browser acceptance run passed switches, branch disclosure, keyboard positioning, connector bends, undo/redo, saved views, SVG/PNG, local print and project-file restore. The first production-shaped image review led to a more compact control header and corrected grouped-feeder labels. Exact review-head verification and final visual comparisons remain release gates.
